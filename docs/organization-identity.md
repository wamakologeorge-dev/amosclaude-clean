# Amosclaud organization identity

Amosclaud supports an organization-native account path that does not depend on email delivery.

## Identifiers

- **Organization ID:** exactly five numbers, for example `11111`.
- **Username:** unique inside one organization, for example `johnM`.
- **Member ID / account ID:** the organization ID plus a four-digit member number, for example `11111-2131`.

The organization ID, username, and member ID are identifiers. They are not authentication secrets. A password is always required for sign-in.

## Account creation

A developer can create an organization by choosing an available five-digit organization ID, organization name, username, and password. The first member becomes the organization owner.

Amosclaud generates three recovery codes. They are shown once and stored only as hashes. The developer must save them outside Amosclaud.

## Adding members

An owner or authorized admin creates a temporary access code. Access codes:

- are generated by Amosclaud;
- are stored only as hashes;
- expire after a bounded time;
- have a limited number of uses;
- can be used to create a new organization membership.

A new member receives a member ID such as `11111-1726` and three one-time recovery codes.

## Sign-in

A developer signs in with:

```text
Organization ID: 11111
Username or member ID: johnM or 11111-2131
Password: **********
```

## Membership removal

Organization owners and authorized admins can revoke a membership by its four-digit member number. Revocation:

- marks the membership as revoked;
- ends the member's active Amosclaud sessions;
- blocks organization-ID sign-in for that membership;
- preserves audit history;
- never reveals the member's password or recovery codes.

An admin cannot remove an owner. The final active owner cannot be removed until ownership is transferred.

The global user record is not erased merely because one organization membership is revoked.

## Recovery

Account recovery requires:

1. the five-digit organization ID;
2. the username or full member ID;
3. one unused recovery code;
4. a new password.

A recovery code is invalidated after use, all existing sessions are ended, and one replacement recovery code is shown once.

## Organization ID changes

Only an organization owner can change the public five-digit organization ID. Member numbers stay the same, but displayed member IDs use the new organization prefix.

## Current scope

This change establishes organization-native identity, membership administration, session revocation, recovery, and audit records. Organization-aware authorization must still be enforced by each repository, workflow, bucket, storage, and agent endpoint before those resources can be described as fully organization-isolated.
