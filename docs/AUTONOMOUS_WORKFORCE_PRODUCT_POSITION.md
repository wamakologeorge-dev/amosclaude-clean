# Product Position: From Cloud IDE to Autonomous Engineering Workforce

Amosclaud should not compete by presenting another empty editor. Its primary product is governed software ownership.

## User promise

A developer can hand Amosclaud a connected repository and a complete work objective. Amosclaud returns one of three truthful outcomes:

1. a verified draft pull request ready for human review;
2. an approval request where human authority is required;
3. an exact blocker with evidence and no unsafe publication.

## Differentiation

- **Ownership instead of autocomplete:** complete work orders, not isolated code suggestions.
- **One accountable autonomous core:** planning, coding, testing, reviewing, and monitoring helpers remain behind one interface.
- **Evidence instead of confidence language:** branch, commit, changed files, checks, verification ID, and pull request.
- **Hybrid execution:** private edge hardware when explicitly eligible, controlled cloud fallback otherwise.
- **Assets instead of projects only:** deployed software can report functional, operational, usage, revenue, and maintenance metrics.
- **Guardrails by construction:** users can narrow policy but cannot disable force-push, protected-branch, verification, secret-masking, rollback, draft-PR, or human-merge controls.

## Human attention policy

The Workforce should interrupt the developer only for:

- initial write authorization when it was not granted with the work order;
- product or architectural judgment that cannot be derived safely;
- unavailable credentials or infrastructure;
- policy, verification, or security blockers;
- final pull-request review and merge;
- production deployment approval.

Routine planning, implementation, testing, bounded repair, evidence collection, and draft-PR preparation remain autonomous.
