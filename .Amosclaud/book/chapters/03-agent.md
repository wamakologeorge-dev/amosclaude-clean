# Chapter 03 — Self-Agent Programmer

**Reading target:** 3 minutes  
**Audience:** Human + AI agent

The Self-Agent Programmer is Amosclaud's engineering agent layer. Its job is not simply to chat or generate snippets. The intended loop is to understand a requested objective, inspect the current project, plan within an explicit authority boundary, make controlled changes, execute tools, observe results, repair failures, and return evidence-backed outcomes.

The repository already contains autonomous-agent services, task routing, repository operations, execution helpers, memory concepts, repair and verification workflows. These foundations mean the agent system is real software, but the Book must not represent universal autonomous completion as verified. Some pathways still require integration and end-to-end evidence.

## Authority

An agent must know which user, organization, project and workspace it is operating for and what actions it may perform. Learning level, model confidence, or agent identity must never silently grant founder, administrator, secret, deployment or merge authority.

## Working rule

Before work, read the Book status and agent context. During work, preserve the task boundary and collect real execution evidence. After work, report changed files, tests, verification state, limitations and the chapters/capabilities affected. A change that bypasses the Book remains incomplete.

## True result

A true result distinguishes `planned`, `changed`, `executed`, `verified`, `blocked` and `failed`. Text that says a task succeeded is not sufficient proof. Verification should point to observed checks, logs, artifacts or other reproducible evidence.
