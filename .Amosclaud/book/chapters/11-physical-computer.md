# Chapter 11 — Physical Amosclaud Computer

**Reading target:** 3 minutes  
**Audience:** Human + AI agent

The Physical Amosclaud Computer is the future appliance form of the software platform. It should not be treated as a generic PC with an Amosclaud logo. The machine should embody the platform layers: Amosclaud runtime, Model, Self-Agent Programmer, SpaceCodeMe, execution and verification, durable data, repository storage, connectors and the control plane.

The target startup path is power on → Amosclaud starts automatically → machine identity is recognized → data and services recover → model becomes available → agent starts → SpaceCodeMe can provision a workspace → software can be built, tested, repaired and verified → evidence and artifacts are retained → approved external connectors can receive results.

A useful hardware status surface can show Agent, Model, SpaceCodeMe, Execution, Network, storage and worker state. Recovery and update controls matter more than decorative gaming features. The system needs reliable cooling, storage, memory, networking and enough compute for the model/workloads chosen for the appliance.

## Software gate before hardware is called finished

The software should demonstrate installation, automatic startup, identity, persistent state, agent task execution, workspace provisioning, build/test/repair/re-test, true-result evidence, artifacts, monitoring, recovery and a successful reboot where required services return automatically.

The Book currently marks the physical computer as `planned`. Architecture and prototype planning are not manufacturing or production proof.

## Book rule

Every appliance milestone—installer image, enrollment, model startup, recovery, updates, hardware telemetry or end-to-end acceptance test—must update this chapter with observed evidence.
